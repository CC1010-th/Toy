权限系统用户、角色与日志管理优化需求说明

1. 需求背景

权限系统后台现有用户管理与角色管理页面缺少按角色快速定位用户的能力。运营或管理员在角色管理中查看角色使用人数后，仍需进入用户管理并重新组合查询条件，操作链路较长。

现有日志管理仅支持用户账号、操作类型和操作时间三个基础条件，操作对象以完整路径拼接展示，无法快速按业务模块、关键词或执行结果定位记录，也难以直观看出操作内容和影响数据规模。

本次优化通过增加角色筛选及跨页联动，提升角色使用情况核查和用户定位效率；同时扩展日志筛选和列表信息，提升操作追踪、问题定位与审计效率。

2. 需求范围

本次包含：

  • 用户管理查询区新增“所属角色”筛选项。
  • 角色管理“使用人数”支持点击并联动至用户管理。
  • 日志管理扩展筛选维度、模块多选能力和日志明细字段。

本次不包含：

  • 商户管理、部门管理、资源管理、数据资源的功能建设或改造。
  • 用户或角色的新增、编辑、删除、状态变更、权限配置、密钥修改及密码重置逻辑调整。
  • 用户与角色数据口径、账号权限模型或服务端权限规则调整。
  • 日志的采集链路、存储周期、脱敏规则、导出能力和服务端审计策略调整。

3. 用户管理

3.1 所属角色筛选

  • “所属角色”位于“商户名称”之后。

  • 控件类型为单选下拉框。

  • 默认状态为“请选择”，表示不限制所属角色。

  • 下拉选项展示可查询的角色名称。

  • 点击查询后，仅展示所属角色与所选角色一致的用户。

  • 点击重置后清空所属角色及其他查询条件，恢复默认用户列表。

  • 从角色管理的使用人数进入时，自动选中来源角色并直接展示筛选结果，无需再次点击查询。

  • 用户管理原有其他查询项、列表字段、字段顺序及既有操作保持不变。

4. 角色管理

4.1 使用人数联动

  • “使用人数”中的数字支持点击。
  • 数字为 0 时仍可点击，以便核查该角色确实没有关联用户。
  • 点击后进入用户管理页面。
  • 用户管理的“所属角色”自动选中被点击行的角色名称。
  • 用户列表自动展示该角色对应的筛选结果。
  • 筛选结果为空时展示空状态，不回退为全部用户。
  • 角色管理原有查询项、列表字段、字段顺序和操作入口保持不变。

5. 日志管理

5.1 查询区

查询区支持以下六个维度组合查询：

  1. 用户账号
  2. 操作模块
  3. 操作类型
  4. 关键词
  5. 操作时间
  6. 结果

各条件之间按“且”关系组合；未填写或未选择的条件不参与过滤。

5.1.1 操作类型

  • 默认值为“全部”。
  • 支持选择具体操作类型，包括查询、导出、新增、修改、删除、审核、登录。
  • 选择具体类型后，仅返回该操作类型的日志记录。

5.1.2 操作时间

  • 采用开始时间和结束时间两个日期时间控件。
  • 时间选择精确到秒。
  • 仅填写开始时间时，返回操作时间大于或等于开始时间的记录。
  • 仅填写结束时间时，返回操作时间小于或等于结束时间的记录。
  • 同时填写时，返回闭区间内的日志记录。
  • 开始时间不得晚于结束时间。

5.1.3 结果

  • 默认值为“全部”。
  • 支持成功、空结果、失败三种结果状态。
  • 选择具体结果后，仅返回对应状态的日志记录。

5.2 操作模块筛选

  • 操作模块采用一级模块和二级模块两层级联选择。
  • 支持单独选择一级模块。选择一级模块后，返回该一级模块下全部日志记录。
  • 支持选择一级模块下的一个或多个二级模块，实现更精确的范围筛选。
  • 支持同时选择多个一级模块或二级模块。
  • 多个模块条件之间按“或”关系匹配；日志命中任一已选模块即保留。
  • 支持按模块名称搜索。
  • 选择器应展示全选、部分选中和未选中状态。
  • 点击确定后应用选择；点击取消不保存本次临时选择；点击清空移除当前临时选择。
  • 未选择任何模块时，表示查询全部模块。
  • 后台菜单超过二级时，本次筛选粒度仍统一收敛至一级模块和二级模块；更深层级内容归入操作对象展示。

5.3 关键词检索

  • 关键词同时匹配“操作对象”和“操作描述”两个字段。
  • 命中任一字段即视为匹配成功。
  • 关键词与用户账号、操作模块、操作类型、操作时间、结果等其他条件组合时，按“且”关系过滤。
  • 关键词为空时不限制操作对象和操作描述。

5.4 操作对象拆分

原“操作对象”完整拼接路径拆分为三个独立字段：

  • 一级模块：系统或一级业务菜单名称。
  • 二级模块：一级模块下的业务分类或二级菜单名称。
  • 操作对象：实际被操作的页面、功能、配置项或业务对象。

展示规则：

  • 三个字段分别成列展示，不再将整条路径直接放入单一字段。
  • 完整路径继续保留，并提供查看完整路径的能力。
  • 只有一级模块的记录，二级模块和操作对象按实际情况使用“—”占位。
  • 只有一级、二级模块而没有更细操作对象的记录，操作对象可展示二级模块或使用“—”，不得出现表格错位。
  • 不同层级深度的记录必须保持相同列结构。

5.5 新增日志字段

5.5.1 操作描述

  • 展示具体操作内容摘要。
  • 查询类操作可展示主要筛选条件。
  • 导出类操作可展示导出范围。
  • 新增、修改、删除、审核类操作可展示对象及变更摘要。

5.5.2 结果

  • 区分成功、空结果、失败三种状态。
  • 不适用或无法提供结果的记录使用“—”占位，不留空白。

5.5.3 数据量

  • 查询和导出类记录展示实际涉及的记录数量。
  • 无结果的查询展示 0。
  • 非数据处理类操作或无法统计的记录使用“—”占位，不留空白。

5.6 日志列表

表格字段依次为：

  1. 序号
  2. 用户账号
  3. 操作时间
  4. 操作类型
  5. 一级模块
  6. 二级模块
  7. 操作对象
  8. 操作描述
  9. 结果
  10. 数据量
  11. 登录 IP

用户账号紧跟序号展示，便于快速识别操作者；各字段按上述顺序固定展示。

6. 验收标准

6.1 用户管理

  1. “所属角色”显示在现有“商户名称”之后，默认显示“请选择”。
  2. 所属角色下拉框可正常展开并选择单个角色；查询后仅展示所选角色的用户。
  3. 所选角色没有用户时显示空状态；重置后清空角色条件并恢复默认列表。
  4. 用户管理原有查询项、列表字段、字段顺序及既有操作保持不变。

6.2 角色管理

  1. 角色管理原有查询项、列表字段、字段顺序和操作入口保持不变。
  2. 每一行使用人数均可点击，包括数值 0。
  3. 点击使用人数后进入用户管理。
  4. 跳转后所属角色自动选中来源角色，且无需再次点击查询。
  5. 跳转后的用户列表仅展示来源角色对应用户；来源角色人数为 0 时显示空状态。
  6. 跳转后用户管理页面标题和侧栏选中态正确。

6.3 日志管理

  1. 日志查询区支持用户账号、操作模块、操作类型、关键词、操作时间、结果六个维度组合查询。
  2. 操作类型默认显示“全部”，可选择查询、导出、新增、修改、删除、审核、登录中的具体类型。
  3. 操作模块支持单独选择一级模块，并返回该一级模块下全部记录。
  4. 操作模块支持选择一级模块下的一个或多个二级模块。
  5. 同时选择多个模块或子模块时，返回命中任一所选模块的全部记录。
  6. 模块选择器支持搜索、多选、确定、取消和清空，并能区分全选、部分选中和未选中状态。
  7. 关键词命中操作对象或操作描述任一字段时，该记录被返回。
  8. 关键词与其他查询条件同时使用时，各筛选维度按“且”关系生效。
  9. 操作时间支持开始时间和结束时间，并可选择到秒。
  10. 仅填写开始时间或结束时间时，可分别按单边时间条件正确筛选；同时填写时按闭区间筛选。
  11. 开始时间晚于结束时间时，系统阻止查询并给出明确提示。
  12. 结果筛选支持全部、成功、空结果、失败，并能返回对应记录。
  13. 日志列表按规定顺序展示 11 个字段，用户账号位于序号之后。
  14. 一级模块、二级模块、操作对象分别独立成列，不再以完整拼接路径占用单一字段。
  15. 仅有一级模块或缺少操作对象的记录使用“—”占位，不因日志层级不同产生字段错位。
  16. 操作对象支持查看完整业务路径。
  17. 操作描述能够展示筛选条件、导出范围或变更内容摘要。
  18. 查询和导出记录展示实际数据量；空结果展示 0；不适用记录展示“—”。
  19. 结果字段能够区分成功、空结果、失败；不适用记录使用“—”占位。
  20. 本次改造不影响用户、角色及日志管理之外的现有功能。
