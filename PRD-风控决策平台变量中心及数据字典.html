一、背景与目标↑

1.1 背景

  1. 风控决策平台以风险因子为单位，分析数据、识别风险并进行处理。
  2. 因子是平台各模块的共同基础，需统一编码与口径。一期优先建设因子体系。
  3. 风控定义因子口径，研发负责计算；平台不加工数据，负责因子的登记、管理和查值。
  4. 一期建设变量中心的因子管理与因子查值，以及数据管理中的数据字典，其余模块另行说明或纳入二期。

1.2 目标

  1. 建立统一的因子目录，口径一致，修改有记录。
  2. 因子从定义到上线的流程在系统里可见、可跟踪。
  3. 支持业务直接查询因子值，用于风险分析。
  4. 按角色控制访问和操作。

二、范围↑

2.1 本期做

  1. 因子管理：因子的查询、查看、新增、编辑、审核、发布、停用、启用、批量导入、导出。
  2. 因子查值：按商户、账号、日期查询因子值，并支持导出。
  3. 数据字典：在「数据管理 › 数据字典」维护业务归属、变量分类（主题分类、因子类别及各类别适用的切片维度）、切片维度（维度及粒度方案）、过滤条件（过滤字段及取值），供因子管理、因子查值读取。
  4. 权限与日志：风控决策平台作为新系统接入现有权限管理系统，在其中登记本期的菜单和权限点，配置部门、用户、角色和商户数据范围；本期的操作日志写入该系统，在其「日志管理」中查看。
  5. 因子来源：因子目录的内容以《投注风控风险因子长清单》（以下简称「长清单」）现行版本为准。下文「因子清单」指因子管理中的列表。
  6. 初始范围：第一批 49 个因子，属于账号基础信息、投注行为-足球单关两个主题，具体因子以风控中心另行提供的清单为准，由研发开发上线。基础变量不登记到因子目录，作为因子计算的数据基础由研发准备。

2.2 适用范围

  1. 系统：风控决策平台为独立系统，有独立入口与菜单，不与现网后台混用。
  2. 用户：风控、研发、运营等内部人员，按角色授权。
  3. 数据：每个用户能查哪些商户，按角色配置的商户数据范围。
  4. 因子主体：账号级因子按「商户 + 账号」计算；商户级因子按商户计算。
  5. 口径：金额统一换算为人民币元；自然日按 UTC+8。

3.2 主要场景

  1. 新增因子：风控点击「新增因子」，填写名称、业务归属、分类，勾选口径（如近7天货量加总：主体账号，来源表 t_order、t_order_detail，求和，按天、窗口 7），填写 SQL 语句，保存草稿后提交审核。
  2. 审核与上线：有风控审核权限的用户查看口径后通过或驳回；研发评估、开发并上线调度作业后研发审核通过，再发布；因子从下一次数据更新起计算。
  3. 修改口径：如归窗字段由下单时间改为确认时间，保存后生成新的主版本，重新审核、发布；新版本发布前旧版本继续运行，已算出的历史结果不变。
  4. 只改属性：如某个因子主要由运营使用，把业务归属由风控改为运营，保存后升次版本，即时生效，不需要审核。
  5. 查看因子值：勾选因子，选商户、账号和日期，查询因子值；结果状态不是「已返回」时看原因；需要时导出，直接下载 CSV。
  6. 长清单更新：长清单更新后，通过批量导入新增因子或批量修正业务归属。
  7. 停用因子：不再使用的因子填写原因后停用，停止计算。
  8. 按角色查看：运营只能看到运行中的因子；查值的商户范围按用户的授权。

5.2.2 审核规则

  1. 审核人不能是提交人本人（风控审核环节）。
  2. 驳回必须写原因。
  3. 因子编码在首次发布前都可以修改（含研发审核通过后），首次发布后锁定；研发审核通过后修改编码的，研发需同步修改已开发的内容。
  4. 发布后从下一次数据更新起生效，已经算出的历史结果不变。
  5. 备注/工单号在研发审核时填写（选填），发布前可以修改：待研发发布时，因子详情底部有「修改备注/工单号」，不发布也可以单独修改；点「发布」时也会带出并可修改；有修改时记入流转记录。因子详情基本信息中显示备注/工单号。
  6. 研发审核时确认 SQL 引用的来源字段存在，系统不做此校验。
  7. 审核通过、发布、驳回在提交时再次校验权限，没有权限时不执行。

5.2.3 版本规则

  1. 新因子首次保存为 v1.0。
  2. SQL 或口径勾选变化：升主版本（如 v1.x → v2.0），重新走审核；新版本发布前，旧版本继续运行。
  3. 只改名称、业务归属、主题类别、说明：
    • 运行中且没有新版本在流程中的因子：升次版本（如 v1.0 → v1.1），即时生效；
    • 有新版本在流程中的因子：新版本为草稿或已驳回时，随新版本一起修改，新版本发布后才生效，期间运行中的版本、因子查值仍显示原来的属性；新版本在待风控审核、待研发审核、待研发发布时不能修改，需等发布后再改，或在待风控审核时由提交人撤回后再改；
    • 未发布的因子：只更新当前版本。
  4. 发布时版本记录新增一条，变更内容为本次属性、口径和 SQL 的变化；新因子写「新因子首次发布」。审核时详情中的「本次变更」同样列出属性、口径和 SQL 的变化。
  5. 已发布因子的新版本为草稿或已驳回时，可以放弃新版本：口径勾选、SQL 和属性恢复为运行中的版本，状态恢复为运行中；版本记录不变，流转记录记一条「放弃新版本」。新版本已提交的，在待风控审核时由提交人撤回后再放弃。

5.2.9 数据就绪

  1. 各输出表按数据日期连续更新，正常情况下不会在中间缺某一天，但各表的最新数据日期可能不同。按输出表判断数据更新到哪一天；未更新的原因包括：源数据未到齐、输出检查未通过（如行数比近 7 天均值偏离超过阈值）。
  2. 查值结果上方的提示：
    • 都已更新：「数据就绪：所选日期内，涉及的 N 张输出表都已更新」；
    • 有未更新：「数据就绪：涉及的 N 张输出表中，有 M 张在 K 天没有更新，这些日期的因子值显示为『未获取』。各输出表最新数据日期：（表名和日期）」，附「查看详情」，弹窗按输出表列出未更新的日期和原因，连续且原因相同的日期合并显示；
    • 只查一天、所选因子来自多张输出表、其中部分当天未更新时：统一改按各表都已更新的最近一天查询，在提示中写明原日期、各表最新数据日期、未更新原因、改用的日期，以及「一次查询的因子取同一数据日期」；
    • 查询日期区间时不调整日期，晚于某张表最新数据日期的值显示「未获取」。

八、依赖与影响↑

8.1 依赖

  1. 因子计算：研发按需求单开发，配置调度任务；平台记录流程，不负责计算。
  2. 因子值查询：按商户、账号、日期、因子读取因子值和结果状态。
  3. 输出表更新状态：用于数据就绪判断。
  4. 权限管理系统：沿用现有的统一账号和权限管理系统（登录、部门、用户、角色、资源、数据范围、日志管理）。本期需要：
    • 接入「风控决策平台」作为新系统，登记 5.2.6 的资源；
    • 接收本平台按 5.2.8 写入的操作日志；审核、发布记为「修改」。
  5. 数据字典：提供业务归属、变量分类、切片维度、过滤条件的选项。切片维度的数据字段、粒度方案（分档依据和档位）以及各因子类别可用的切片维度，需要在字典中配置完整（见 5.2.11）。

8.2 影响

风控决策平台为独立系统，有独立入口与菜单，不与现网后台混用。权限管理系统只新增本平台的资源、权限分配和操作日志，不影响其他系统已有的资源和授权。

8.3 风险与注意

  1. 长清单只是提纲：风险因子长清单是因子提纲，不对其中的因子逐条检查；具体因子内容由开发单独确认，按本文的录入和导入规则进入平台。
  2. 切片维度只做 4 个：风险因子长清单（1120）两个页签的「可按」中还有比赛范围、联赛、赛事、下单赔率数据源、商户等 14 个维度，本期字典不配置；按这些维度切片的因子，口径勾选中不能记录切片，切片只写在 SQL 中。

十一、开发测试重点说明↑

  1. 同一数据日期：一次查询中的所有因子取同一个数据日期；只查一天且部分表未更新时，统一改按都已更新的最近一天，并给出提示。
  2. 结果状态不显示为 0：无法计算、未获取、不适用都显示「—」和原因，不能显示成 0。
  3. 无效组合不出行：账号不在所选商户下时不出行；全部无效时显示「查询无数据」，而不是一堆「未获取」。
  4. 商户级因子：按所选商户逐行输出，账号为「—」；排序时始终在账号行后面。只选商户级因子时账号可以不填。
  5. 页面不限条数：页面按分页显示全部结果；导出直接下载 CSV，日期区间最多 90 天。
  6. 重复校验：名称、编码、SQL 重复时拦截；SQL 比较时忽略注释、空格和大小写。口径勾选相同只提醒，确认后可以保存，只和同一主题、同一类别下做过勾选的因子比较。编辑时都排除因子自身。
  7. 编码锁定：首次发布前都可以修改编码，首次发布后锁定。
  8. 版本与生效：改 SQL 或口径勾选才升主版本；新版本发布前查值仍用旧版本，结果中的「定义版本」显示实际使用的版本。
  9. 审核人限制：审核时校验提交人，本人不能审核自己提交的因子。
  10. 批量导入：系统内已有的编码按修改处理，走与编辑相同的版本规则和状态限制；名称、SQL 的重复校验排除因子自身。主题分类、因子类别按名称与数据字典完全一致匹配，不一致的整行拦截，不自动新增。
  11. 权限在服务端校验：每次提交操作时都要重新校验，不能沿用弹窗打开时的结果；菜单、按钮、商户数据范围都在服务端校验，页面隐藏只是展示；没有权限的查询也记日志。
  12. 只读角色：只有菜单权限、没有编辑或审核权限的用户，只返回运行中的因子。
  13. 授权来源：菜单、按钮、商户范围都读取权限管理系统的授权结果，本平台不另存一份授权。
  14. 日志写法：操作对象按 5.2.8 的格式写，审核、驳回、停用要带上意见或原因；因子清单的查询和查看详情不记。
  15. 编码自动生成：只有没手动改过的编码才跟随勾选变化；编辑已有因子时保留原编码，点击「按勾选重新生成」才重新生成；研发审核通过后不再生成。
  16. 切片维度：只选维度和粒度方案，不选取值，每个取值或每档都输出结果；只统计部分取值的，写在过滤条件和 SQL 中。可勾选的维度按因子类别配置，启用的维度都可以勾选；粒度方案填了「只细分」的，只把该取值分档，其余取值照常输出。比率类因子切片后的分子、分母以 SQL 为准，在因子说明中写明。
  17. 选项不写死：业务归属、分类、切片维度、粒度方案、各类别可用的切片维度及过滤条件都读取数据字典；字典改动后不需要改本平台。
